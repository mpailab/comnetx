# Results Registry

This directory is generated by:

```bash
python scripts/paper/collect_results_registry.py
```

It consolidates all JSON measurements under `results/` into searchable tables.
Repeated runs with the same launch parameters are preserved for stability
analysis. Fully identical or near-identical time/metric series are collapsed and
listed in `deduplicated_sources.*`.

## Files

- `all_results.csv` / `all_results.json`: compact searchable registry without
  per-update series.
- `all_results_with_series.json`: full registry with the original per-update
  measurement series.
- `summary_by_run_key.csv` / `summary_by_run_key.json`: grouped view by method,
  dataset, batch strategy, and parsed algorithm parameters; includes means and
  standard deviations across repeated runs.
- `errors.csv` / `errors.json`: launcher failures collected from
  `errors_*.json`.
- `deduplicated_sources.csv` / `deduplicated_sources.json`: exact or near-exact
  duplicates that were not copied as separate experiment records.
- `manifest.json`: counts and output paths for the latest registry build.

## Useful Columns

- `measurement_type`: `experiment` or `neighborhood`.
- `source_owner`: first directory below `results/`, e.g. `paper_icdm`,
  `drobyshev`, `konovalov`, `egorov`, `archive`, or `neighborhood`.
- `method`, `mode`, `subcoms_depth`, `radius`, `aggregation`, `feature_mode`:
  parsed from the algorithm string when present.
- `base_dataset`, `force_undirected`, `batch_strategy`, `machine`: launch
  parameters used to identify overlapping runs.
- `stream_key`: derived launch-stream key combining source file, machine,
  dataset, directedness, batch strategy, and completed update count. It is used
  to pair baseline/local algorithms measured on the same dynamic stream.
- `stream_id`: compact hash of `stream_key`, suitable for paired analyses.
- `measurement_id`: compact hash of the source context plus `series_digest`,
  suitable for identifying the exact measured algorithm-output series without
  merging different algorithms in the same stream.
- `run_key`: grouping key without machine, useful for comparing repeated runs
  of the same original algorithm string and launch parameters.
- `run_key_with_machine`: stricter key used for duplicate detection.
- `final_modularity`, `total_time`, `final_nmi`: compact metrics extracted from
  the final update when present.

Near-duplicate detection rounds non-time numeric fields to 6 decimal digits and
time fields to 3 decimal digits before hashing the full per-update series.
