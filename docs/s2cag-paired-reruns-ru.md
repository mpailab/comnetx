# Запуск парных повторных замеров S²CAG на сервере

Инструкция относится к полному исследовательскому checkout с установленной
интеграцией S²CAG. В публичном архиве evidence эта сторонняя интеграция заменена
описательной заглушкой; сам по себе архив позволяет восстановить таблицы и
рисунки, но для новых запусков S²CAG нужны внешние компоненты, перечисленные
в `docs/third-party-components.md`.

На сервере перейдите в существующий checkout ComNetX и обновите ветку:

```bash
git fetch origin
git switch codex/ieee-access
git pull --ff-only origin codex/ieee-access
```

Затем из корня репозитория запустите **один скрипт**:

```bash
bash scripts/paper/run_s2cag.sh --paths-config datasets-info/paths/cn69.json
```

Скрипт сразу выполняет основную серию: **PubMed и arxivmath**, протоколы
**999:5 и 999:10**, random features 64/seed 42, **пять повторов каждой пары**.
В паре запускаются full S²CAG и ComNetX с S²CAG — всего **20 пар / 40 процессов**.
Отдельных диагностических запусков, preflight и профилирования ComNetX нет.

При первом запуске скрипт создаёт `.venv-s2cag` и устанавливает фиксированные
зависимости. На сервере нужен Python **3.10 или 3.11**, поддержка `venv`, доступ
к пакетам при первой установке и уже подготовленные данные по указанному JSON.
Если Python не находится автоматически:

```bash
bash scripts/paper/run_s2cag.sh --python /path/to/python3.11 \
  --paths-config /path/to/server-paths.json
```

По умолчанию тензорная часть использует CUDA; NumPy/SciPy-решатель S²CAG — CPU.
При недоступности CUDA запуск остановится. Для намеренной отдельной CPU-серии
добавьте `--device cpu`. Восемь CPU-потоков зафиксированы в конфигурации серии.

Результаты сохраняются в новый каталог `results/s2cag-paired/<UTC-время>-<PID>/`.
Можно задать имя явно через `--output-dir results/s2cag-paired/server-run-01`;
существующие каталоги не перезаписываются. Внутри находятся:

- `paired-summary.json` — проверенные парные ΔQ, ΔNMI и ускорения;
- `pairs/` — результаты и метки после каждого обновления;
- `jobs/*.log` — журналы отдельных исполнений, включая traceback при ошибке;
- `campaign.json`, `initial/`, `execution-sources.zip` — параметры, единая
  начальная иерархия, версии библиотек, хеши входов и исходники исполнения.

Для длительного запуска, сохраняющегося после выхода из SSH:

```bash
nohup bash scripts/paper/run_s2cag.sh \
  --paths-config datasets-info/paths/cn69.json \
  > s2cag-run.log 2>&1 &
tail -f s2cag-run.log
```

Одновременно на том же CPU/GPU не запускайте другую измерительную кампанию.
Скрипт последовательно чередует порядок full/local, проверяет одинаковые входы
и начальные метки, сохраняет все реальные обновления. Один небольшой внутренний
прогрев решателя исключён из измеряемого времени. Bootstrap, применение batch,
внешние метрики и запись файлов также исключены. Полное время обработки и
время за вычетом preprocessing сохранены отдельно; densification и внутренние
метрики S²CAG входят в оба интервала. Пять внутренних вызовов решателя не
подменяют пять внешних повторов; возвращается последний результат.

Используется сохранённый S²CAG `sub`: T=10, α=1, τ=7, пять вызовов, SVD seed 0,
100 шагов округления. ComNetX: L=3, r=1, среднее по атому. Full получает k из
предыдущих меток, local — из числа атомов; k, ширина embedding и число непустых
групп записываются раздельно. Начальная иерархия строится публичным `leidenalg`.
Закрытый `dynamic_graphs_communities` не требуется.

Отдельное окружение необходимо из-за сохранённого округления S²CAG:
SciPy 1.11 изменил [деление sparse/dense](https://docs.scipy.org/doc/scipy/release/1.11.0-notes.html#scipy-sparse-improvements),
на прежнее поведение которого опирается этот код. Поэтому задан SciPy 1.10.1,
а исходные функции решателя не переписываются. Это новая контролируемая серия;
её результаты не смешиваются с архивными запусками неизвестной версии.
